The problem

Transfer arrivals, traffic, vehicle capacity, and dispatch timing interact. A locally sensible rule, such as sending an extra bus toward anticipated demand, can still worsen service elsewhere. TransitOps models those interactions across a four-stop corridor.

Core decision

Compare policies under the same scenario

The API runs baseline and adaptive cases for 60 simulated minutes using seed 17 and the same input parameters. It returns metrics, event logs, and a timeline so that a result can be traced back to operating decisions.

Two simulation paths

The Python corridor model advances passenger queues, vehicles, and dispatch in minute steps; FastAPI exposes the comparison to the web interface. A separate SUMO / TraCI path steps microscopic traffic, applies signal-priority actions, and produces vehicle and signal telemetry. They are distinct models, not interchangeable evidence.

Adaptive rules with explicit conditions

The corridor engine combines scheduled dispatch every ten minutes with demand-based pre-staging. It looks ahead to transfers and compares demand with arriving capacity. Signal priority requires a delayed, sufficiently occupied bus. The separate TraCI controller uses a 70 m approach threshold and a 15-second cooldown per signal.

Result / A hypothesis to revise

The adaptive case increased average wait by 1.70 minutes using unrounded values, and left 25 more passengers waiting. More interventions did not produce better service in this scenario.

Inputs: traffic multiplier 1.25, train delay 5 minutes, transfer demand 135, fleet size 4. Both cases generated 497 passengers. One scenario does not establish performance across a network.

What this comparison changes

The next experiment should isolate pre-staging and signal priority, sweep demand and traffic conditions, and compare multiple seeds. Average wait here includes passengers who boarded, so it must be read alongside the queue remaining at the end. This prevents a policy from looking good simply because hard-to-serve passengers never boarded.

Scope and reproducibility

The corridor model uses synthetic demand and simplified travel times; it is not calibrated to an operating transit agency. SUMO telemetry projects a synthetic corridor onto geographic anchors. The result table comes from the corridor engine, not the SUMO path. A reproduction script is included in this change’s review materials.
