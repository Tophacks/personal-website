Why I built it

As Quadmates began organizing contributors, recruiting candidates and coordinating work, small tasks accumulated: who had applied, who needed onboarding, who had submitted hours and which projects were blocked. Staffflow consolidates those workflows into a role-aware application rather than relying on disconnected tools.

Service boundaries

The frontend is React with routes for applicants, candidates, employees and managers. The Express API enforces access controls and handles operations using Supabase Postgres and private document storage. Staffflow data uses a dedicated set of table names, separate from Quadmates product entities.

Design principle

Make status actionable

The dashboard presents pending approvals, onboarding work, blocked deliverables and unread notifications. Unavailable API data is not silently represented as zero work.

Assessment automation, with an explicit boundary

Templates include code-reading questions scored deterministically on the server and work samples that remain subject to human review. Candidate workspaces save draft progress, protect against accidental resets, and apply server-enforced deadlines. Submitted code is stored as text and not executed by the Express API.

A production coding-execution product would require a separately isolated judge, strict resource limits, abuse protections and versioned hidden cases, rather than evaluating untrusted code inside the web server.

State transitions and safety

Hiring stages link applicants to candidate workspaces. Roles can associate a default assessment and conversion can assign it automatically. Employee and manager views are separate, with permission checks on backend routes. The roadmap prioritizes invitation delivery, scheduling overlap checks and reporting.

What the code demonstrates

React route separation, Supabase-backed operations, candidate invitation tokens, assessment submissions, scheduled reminders, CSV hours reporting, notification records and organization hierarchy endpoints. Production operating metrics and independent penetration-test results are not claimed.

Limitations and next validation

Multi-tenant isolation has not been validated; Staffflow is currently configured as one organization workspace. The system is not a payroll-processing engine. Deliverability depends on configured email credentials. Scheduling overlap prevention requires concurrent-write testing. Automated scoring must not substitute for human review of candidates.
