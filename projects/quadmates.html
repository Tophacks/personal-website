Project responsibilities and foundations

Product direction and the discovery-to-session workflow. The case study covers matching rules, requests, and conversation behavior.

React handles the interface; Supabase supplies authentication, Postgres, storage, and realtime infrastructure.

The problem

A shared course is a useful starting point, but a study partnership also needs compatible schedules, preferences, and a way to make contact. Quadmates brings discovery, requests, messaging, groups, and session coordination into one product.

Implementation focus

Make recommendations explainable

The compatibility function returns a score alongside shared courses, overlapping minutes, and shared study styles. The system can show the reasons behind a recommendation rather than presenting a score without context.

One product, distinct responsibilities

React client handles discovery and conversation state. Express routes check membership and persist messages. Supabase provides authentication, Postgres, storage, and broadcast events. Persisted history and realtime updates meet in the chat component.

A small, inspectable ranking model

Course overlap contributes up to 50 points, availability up to 35, and study style up to 15. Courses are normalized for case and whitespace; the components saturate at three shared courses, ten hours of shared availability, and two shared styles. This is a deterministic heuristic, with weights that can be inspected and revised.

Illustrative calculation from the function: two shared courses + five overlapping hours + one shared style → round(33.33 + 17.5 + 7.5) = 58/100. This is an example, not a user result.

Keep the write path separate from delivery

The message route stores a message before broadcasting it. The chat UI merges responses and broadcast events by message ID to avoid showing duplicates. Failed sends retain the draft and expose a retry action. Typing notifications are throttled to roughly one update per 1.8 seconds, reducing event traffic while preserving feedback.

Delivered in the repository

Compatibility scoring, request acceptance, direct and group message routes, notification deduplication, and a chat interface with retry and reconnect states are implemented.

The current frontend is React + Vite; the previous portfolio’s Next.js label was inaccurate. No adoption, retention, latency, or security-audit result is claimed here.

Trade-offs and next validation

Fixed ranking weights make behavior understandable, but they are not calibrated against completed study sessions. Pairwise availability overlap can double-count overlapping entries; input normalization and edge-case tests are useful next work. Message persistence and broadcast delivery are separate operations, so reconnect recovery needs end-to-end verification. Route-level checks alone do not establish the security of realtime subscriptions.
