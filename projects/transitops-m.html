03 / Fleet state machine / Physical design constraints

TransitOps-M

A miniature fleet concept with software rules for reserving a depot bay, confirming arrival, and recovering from a stop.

Python dataclassesState machineFastAPI dashboardFreeCAD macrosHO 1:87 concept

The problem

A command to return to a depot is not evidence that a vehicle has arrived. The dispatcher distinguishes a reserved bay from an occupied bay, and requires a separate confirmation before treating docking as complete.

Design boundary

Test the logic before connecting hardware

The dispatcher is independent of motors, sensors, and charging. A caller injects mock docking confirmation; the dashboard exposes simulation state. Physical integration remains future work.

Reservation and occupancy are separate state

Request depot: check availability, reserve the automated bay, mark the bus returning. Confirm docked: require a matching reservation and clear interlock, then assign occupancy. Dispatch: verify occupancy and release the bay.

Recovery must be deliberate

An emergency stop faults moving vehicles and clears reservations. Clearing the interlock does not resume motion: a faulted bus must be reset to holding. This encodes recovery as an explicit operator action rather than an incidental consequence of clearing a flag.

Verification / 8 existing tests passed locally

The suite covers station tracking and dwell, simulation reset, depot flow, double-booking rejection, safe stop, docking confirmation, and invalid tick counts. These checks establish modeled behavior, not physical safety.

CAD reveals a different set of constraints

The Depot B macro studies two active lanes and three staging slots on a 280 × 280 mm slab. The current dispatcher models one automated bay and two static parking bays, so the CAD and software capacities are not yet aligned. The CAD notes also identify 44 mm active lanes against an approximately 50 mm straight-road planning reference; swept paths and the selected chassis still need validation.

Next integration milestone

Agree on one depot configuration, reconcile the software and CAD, then implement a sensor adapter that can distinguish requested, confirmed, and faulted transitions. The present design has no real motor or charging control and is not fabrication-ready.
